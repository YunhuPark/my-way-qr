# 내 방식 QR 사용자 테스트 계획

## 1. 목적과 가설
- **목적:** QR 프로필이 적용된 화면("내 방식 화면")이 기본 키오스크 화면보다 고령자 등 키오스크 이용이 어려운 사람에게 더 쉬운지 확인한다. 성과보고서의 "검증 결과" 근거로 쓴다.
- **가설**
  - H1: 내 방식 화면에서 과업 완료 시간이 짧다.
  - H2: 내 방식 화면에서 도움 요청·막힘(되돌아가기, 잘못 선택)이 적다.
  - H3: 내 방식 화면에서 도움 없이 끝낸 비율이 높다.
  - H4: 참가자가 프로필(QR)을 스스로 만들 수 있다. (생성기 사용성)
- **제안서 목표와의 연결:** 후보작 제안서의 솔루션 챌린지 목표는 "2개 이용과제 MVP에서 **독립 완료율 30% 향상, 도움요청 절반 감소**를 검증"이다. 이 테스트의 "도움 없이 성공한 비율"(독립 완료율)과 "도움 요청 횟수"가 같은 지표이므로 보고서에 같은 말로 쓴다. 단, 결과가 이 목표에 못 미쳐도 있는 그대로 적는다. (목표는 제안자의 가설이지 합격 기준이 아니다.)
- **한계(보고서에도 명시):** 소규모 탐색적 테스트이며 통계적 유의성을 주장하지 않는다. 실제 키오스크가 아닌 모의 환경이다.

## 2. 참가자
- **인원:** 6명 목표 (최소 4명). 한 명당 20분 내외.
- **대상:** 키오스크 사용이 불편하다고 느끼는 성인. 고령층(60대 이상) 위주, 가능하면 시력·읽기·이해에 어려움이 있는 분. 미성년자는 제외.
- **모집:** 가족·이웃·지인 소개 우선. 복지관·경로당 협조는 시간이 걸리므로 병행 시도.
- **편향 기록:** 지인 모집이면 보고서에 그대로 적는다.
- **윤리·개인정보**
  - 이름 대신 P1~P6 코드로만 기록하고, 연령대·성별·키오스크 사용 빈도 정도만 받는다.
  - 장애·건강 상태는 묻지 않는다. 본인이 말하면 기록 여부를 먼저 묻는다.
  - 사전 동의서: 자발적 참여, 언제든 중단 가능, 수집 항목, 사진·영상 촬영은 별도 동의(촬영은 화면과 손만, 얼굴 제외 권장), 결과 보고서 활용.
  - 어려움을 느껴도 참가자의 부족함이 아니라 "화면의 문제"라고 먼저 안내한다.

## 3. 설계 (참가자 내 비교, 순서·과업 교차)
각 참가자는 **두 과업**을 한다. 한 과업은 기본 화면, 다른 과업은 내 방식 화면이다. 학습 효과와 과업 난이도 차이를 줄이려고 아래처럼 돌려 배정한다.

| 참가자 | 1번째 과업 | 2번째 과업 |
|---|---|---|
| P1 | 카페 (기본) | 민원 (내 방식) |
| P2 | 민원 (기본) | 병원 (내 방식) |
| P3 | 병원 (기본) | 카페 (내 방식) |
| P4 | 카페 (내 방식) | 병원 (기본) |
| P5 | 민원 (내 방식) | 카페 (기본) |
| P6 | 병원 (내 방식) | 민원 (기본) |

- 4~5명이면 위 표의 앞에서부터 사용한다.
- 같은 과업을 두 번 하지 않으므로 외운 효과가 적다.
- 과업 문구는 시나리오 카드로 읽어 준다. (예: 카페 — "여기서 마실 아메리카노를 카드로 결제해 보세요.")

## 4. 진행 순서 (약 20분)
1. **인사·동의서** (3분): 목적 설명, 동의서 서명, 코드 부여.
2. **사전 질문** (1분): 연령대, 키오스크 사용 빈도, 주로 어려운 점 한 줄.
3. **내 화면 설정 만들기** (3분): 참가자가 "화면을 어떻게 보고 싶은지" 말하고, 생성기가 설정한 뒤 직접 고쳐 보게 한다. 도움 요청과 소요 시간을 기록한다.
4. **과업 1** (4분) → 만족도 3문항.
5. **과업 2** (4분) → 만족도 3문항.
6. **마무리 인터뷰** (3분): 아래 열린 질문 3개.

## 5. 측정 항목 (과업마다 기록)
| 항목 | 정의 | 기록 방법 |
|---|---|---|
| 완료 시간(초) | 첫 화면 → 완료 화면 | 스톱워치 (또는 앱 로그, 7장) |
| 성공 | 도움 없이 완료 = 성공 / 힌트 1회 = 도움받음 / 중단 = 실패 | 관찰 체크 |
| 막힘·오류 횟수 | 뒤로 가기, 잘못 선택 후 수정, 화면 앞에서 5초 이상 멈춤 | 관찰 체크 |
| 도움 요청 횟수 | 진행자에게 묻거나 힌트를 받은 횟수 | 관찰 체크 |
| 시간 초과 | 제한 시간으로 처음으로 돌아간 횟수 | 관찰 체크 |

- **만족도 (과업 직후, 1~5점)**
  - Q1. 화면의 글이 읽기 쉬웠다.
  - Q2. 다음에 무엇을 해야 하는지 알 수 있었다.
  - Q3. 실제 키오스크에서도 이런 화면이면 쓰고 싶다.
- **마무리 인터뷰 (열린 질문)**
  1. 어떤 점이 가장 편했나요?
  2. 어떤 점이 여전히 불편했나요?
  3. 평소 키오스크에서 가장 힘든 순간은 언제인가요? 이 서비스로 해결되나요?

## 6. 분석과 보고서 기재 방식
- 인원이 적으므로 **평균 대신 중앙값과 개별 값**을 함께 제시한다. (표로 P1~P6 모두 공개)
- 기본 화면과 내 방식 화면의 완료 시간 중앙값, 성공률, 막힘·도움 횟수 합계, 만족도 평균을 비교한다.
- 시간 초과는 기본 화면에만 있는 "30초 제한"의 영향이 섞이므로 **따로 보고**하고, 가능하면 시간 초과가 없었던 시도만 모은 비교도 함께 낸다.
- 예상과 다른 결과(개선이 없거나 오히려 불편)도 숨기지 말고 쓴다. 개선 포인트로 활용한다.
- **성과보고서 문장 틀:**
  > 연령대 [OO]의 키오스크 이용 불편자 [N]명을 대상으로 기본 화면과 내 방식 화면을 비교한 결과, 완료 시간 중앙값은 [OO초 → OO초], 도움 없이 완료한 비율은 [OO% → OO%], 막힘·도움 요청은 [OO회 → OO회]였다. (소규모 탐색적 테스트)

## 7. 도구 준비
- **기록지:** P코드별 표 (조건·순서·시간·성공·막힘·도움·시간 초과·만족도 Q1~Q3·메모).
- **시나리오 카드:** 과업 3종을 큰 글씨로 인쇄.
- **환경:** 같은 노트북·휴대폰, 같은 화면 크기. 공개 URL로 접속(QR은 참가자 휴대폰 또는 인쇄물).
- **앱 자동 기록(구현됨):** 키오스크 주소 뒤에 `?test=1&pid=P1`을 붙이면 진행자용 패널이 나타난다. (내 방식 화면은 `&p=...` 프로필 값도 함께)
  - 진행: 참가자 코드 입력 → **과업 시작** → 참가자가 수행 → 완료 화면이 뜨면 자동 저장. 진행자가 힌트를 주면 **도움 +1**, 포기하면 **중단(실패)**을 누른다.
  - 자동 기록: 완료 시간, 오선택(과업 카드의 정답과 다른 선택), 뒤로 가기, 시간 초과, 선택 순서. 결과는 성공/도움받음/실패로 구분된다.
  - 기록은 **그 기기의 브라우저에만** 저장되므로 같은 기기·같은 브라우저로 진행하고, 세션이 끝날 때마다 **CSV 내려받기**로 백업한다. 파일럿 기록은 지운 뒤 본 테스트를 시작한다.
  - 자동 기록이 못 잡는 것(5초 이상 멈춤, 만족도, 인터뷰)은 종이 기록지에 적는다.
